# 50-processes

Standard operating procedures: how a recurring task is actually done
here, step by step, so someone else can repeat it.

**Rules here:** `type: sop`. Every SOP needs purpose, scope, roles,
numbered steps, exceptions and a change history — shape in
[../_templates/sop-note.md](../_templates/sop-note.md). Steps are
imperative and checkable ("open X, click Y"), never "usually one would".
Binding only with `status: stable` AND a `verified:` entry; a `draft`
describes an intention, not the rule. Never edit a `stable` SOP
silently: raise `version`, add a history line, reset `review_due`.
**Company mode also requires** `owner`, `audience`, `confidentiality`,
`review_due` — an SOP without an owner rots.
**NOT here:** one-off tasks → the project or the inbox. WHY it is done
this way → [../40-decisions/](../40-decisions/index.md); the SOP links
the decision instead of repeating it. Who is responsible in general →
`60-roles/` (company mode).
