# 50-processes

Standard operating procedures: how a recurring task is actually done
here, step by step, so someone else can repeat it.

**Rules here:** `type: sop`. Every SOP needs purpose, scope, roles,
numbered steps, exceptions and a change history — the shape is in
[../_templates/sop-note.md](../_templates/sop-note.md). Steps are
imperative and testable ("open X, click Y"), never "usually one would".
An SOP is only binding with `status: stable` AND a `verified:` entry; a
`draft` describes an intention, not the rule. Never edit a `stable` SOP
silently: raise `version`, add a line to the change history, reset
`review_due`. **In company mode also required:** `owner`, `audience`,
`confidentiality`, `review_due` — an SOP without an owner rots.
**NOT here:** one-off tasks → the project or the inbox. WHY something is
done this way → [../40-decisions/](../40-decisions/index.md); the SOP
links the decision instead of repeating its reasoning. Who does what in
general → `60-roles/` (company mode).
